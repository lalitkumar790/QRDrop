File reconstructedYour browser has reconstructed the file in memory.

The received file stays in browser memory until you save it or close/reload the page. Saving necessarily writes the file to your device. QRDrop itself has no file server or cloud storage.

⌁

Optical only

File contents travel as visible QR frames from one screen to another. No WebRTC, local-network transfer, cloud upload, or relay is used.

◌

Browser memory

QRDrop does not persist transferred files. The receiving browser holds chunks in memory; a user must explicitly save the reconstructed file.

!

Know the limits

Optical transfer is slow. Camera scanning depends on browser support. The page needs a one-time online load unless it has already been installed/cached.
